# Documentation Rules

**Project:** Adversarial Attack Detection for Large Language Models (LLMs)
**Status:** ACTIVE

## Core rules

1. The official project name is always recorded as: `Adversarial Attack Detection for Large Language Models (LLMs)`.
2. `DGAD` is a non-authoritative working term only. It must never be presented as the official project name, framework name, or approved research title.
3. False agreement is documented as an evolving proposal under investigation. It does not imply a project rename, finalized framework, or proven method.
4. Documentation must not claim experimental results, final benchmark roles, or final dataset statuses without explicit approval.
5. Documentation may record unresolved items as `Status: UNDER INVESTIGATION` or `Status: EXPERIMENTAL`.
6. The `docs/` tree is the authorized documentation workspace. `Dataset/` and `PHASE-3/` remain read-only references unless a specific decision authorizes otherwise.

## Naming conventions

- Use the official project name in headers and major documents.
- In architecture discussions, a phrase such as "current working architecture concept, informally referred to as DGAD" is acceptable when needed.
- Prefer neutral wording such as "proposed false-agreement-aware architecture" or "current research architecture" instead of a definitive framework label.

## Evidence handling

- Do not infer final dataset roles from benchmark packaging alone.
- Do not write experimental claims without evidence.
- Distinguish between repository evidence, provisional classifications, and approved decisions.

## Boundary discipline

This documentation workflow may not edit forensic, governance, or dataset artifacts under `PHASE-3/` or `Dataset/` without separate authorization.

## Repository status note

Git is installed in the environment. The project directory is simply not yet initialized as a Git repository. A missing Git repository state does not imply missing Git tooling.
